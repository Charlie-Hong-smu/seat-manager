# Agent operating guide

Read this file before changing the repository. The durable architecture and deployment details live in `docs/ARCHITECTURE.md` and `docs/OPERATIONS.md`. Version classification, natural-language release intent, and edition boundaries are governed by `docs/VERSION_GOVERNANCE.md`; read it before planning any feature or release.

Before changing any visible UI, layout, interaction, or animation, read `docs/DESIGN_SYSTEM.md`. It is the visual source of truth for both editions. New conversations must not infer a new style from one isolated screen or invent a parallel component language.

## Source of truth

- `frontend-react/` is the only application frontend source.
- `cloudflare-worker/` owns license, manual sync, and AI endpoints.
- `netlify/functions/worker-proxy.mjs` is the commercial network proxy; every new public app route must be allowed there and covered by the route-contract test.
- `license-admin/` is the private license administration page.
- Build output is generated by CI and must not be committed.
- `frontend-react/src/app/components/ui.tsx` is the canonical shared UI primitive entry point. Reuse or extend it before creating a visually equivalent local control.
- `frontend-react/src/styles/theme.css` owns shared visual tokens and motion primitives. Do not introduce a second token file or page-local design system.

## Non-negotiable compatibility

- Preserve the `seat-manager-workspaces-v1` workspace book, the legacy `homeroom-seat-manager-v1` import path, backup JSON, cloud-sync payloads, Worker routes, KV keys, and secret names.
- Zhang and Commercial both use product-license login and device limits. Existing local-password data remains untouched for compatibility but is not an active login path.
- Missing feature classification defaults to Zhang early access. Commercial frontend deployment requires explicit promotion of an already verified Zhang commit.
- AI may prepare suggestions, but it must never write teacher data without an explicit teacher confirmation.
- Manual cloud backup/restore remains manual. Do not add realtime sync or automatic conflict merging.
- Do not commit secrets, `.dev.vars`, local tool state, caches, or `promo-video/`.

## Required workflow

1. Inspect the dirty worktree and preserve unrelated user changes.
2. Keep changes scoped to the requested feature or refactor.
3. Run frontend lint, strict typecheck, `test:coverage`, both edition builds, `check:size`, Worker tests, and relevant browser smoke tests before handoff.
4. Commercial release checks must run `check:production`; mocks and Playwright routes belong only in `frontend-react/e2e/`.
5. When an app endpoint changes, verify the frontend call, Worker route, Netlify allowlist, and deployment workflow together.
6. Update durable documentation when architecture, storage, public routes, deployment, or validation commands change.
7. For UI work, run `pnpm check:design` and compare the result against the acceptance checklist in `docs/DESIGN_SYSTEM.md`. If a new visual pattern repeats twice, promote it to `ui.tsx` or `theme.css` instead of copying classes a third time.
8. For local interactive UI debugging, default to `cd frontend-react && pnpm dev --host 127.0.0.1` and open the printed `/seat-manager/` URL. Use the localhost-only **进入本地预览** action instead of a product license; it creates only a temporary development session and does not consume a device slot. Do not use `vite preview` for routine manual debugging: preview mode intentionally behaves like a production build and still requires product-license login. Use it only when validating a production build, PWA, or release artifact.
9. When a reported defect or UX issue could come from a shared pattern, search the shared primitive and all equivalent call sites before patching one screen. Classify matches by business semantics, fix every safe instance with the same root cause in the current change, and add shared regression coverage. If a match is intentionally excluded because its cancel/discard semantics differ, record that boundary in the handoff instead of silently ignoring it.

Use pnpm for `frontend-react/` and npm for `cloudflare-worker/`. Do not mix lockfile owners.
