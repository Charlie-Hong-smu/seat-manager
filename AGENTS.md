# Agent operating guide

Read this file before changing the repository. The durable architecture and deployment details live in `docs/ARCHITECTURE.md` and `docs/OPERATIONS.md`.

## Source of truth

- `frontend-react/` is the only application frontend source.
- `cloudflare-worker/` owns license, manual sync, and AI endpoints.
- `netlify/functions/worker-proxy.mjs` is the commercial network proxy; every new public app route must be allowed there and covered by the route-contract test.
- `license-admin/` is the private license administration page.
- Build output is generated by CI and must not be committed.

## Non-negotiable compatibility

- Preserve the `seat-manager-workspaces-v1` workspace book, the legacy `homeroom-seat-manager-v1` import path, backup JSON, cloud-sync payloads, Worker routes, KV keys, and secret names.
- The default Zhang edition keeps local-password login. The commercial edition keeps product-license login and device limits.
- AI may prepare suggestions, but it must never write teacher data without an explicit teacher confirmation.
- Manual cloud backup/restore remains manual. Do not add realtime sync or automatic conflict merging.
- Do not commit secrets, `.dev.vars`, local tool state, caches, or `promo-video/`.

## Required workflow

1. Inspect the dirty worktree and preserve unrelated user changes.
2. Keep changes scoped to the requested feature or refactor.
3. Run `pnpm check`, both edition builds, Worker tests, and relevant browser smoke tests before handoff.
4. When an app endpoint changes, verify the frontend call, Worker route, Netlify allowlist, and deployment workflow together.
5. Update durable documentation when architecture, storage, public routes, deployment, or validation commands change.

Use pnpm for `frontend-react/` and npm for `cloudflare-worker/`. Do not mix lockfile owners.
