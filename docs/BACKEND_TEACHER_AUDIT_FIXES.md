## 兼容与发布边界

发布本身不立即强制所有旧产品凭证重新登录。兼容条件是：旧凭证仍有合法签名、未过期、当前授权有效、租户/版本匹配、设备仍绑定，且凭证和设备记录都没有会话 UUID。该设备下一次登录会写入新的 UUID 并签发包含 UUID 的 token，此前旧 token 随即失效，仍持有旧 token 的会话需要重新登录。正式协调器路径在每次鉴权时读取当前权威授权；停用、删除、到期、解绑或清空绑定后，拒绝旧 token 发起的新同步/AI 请求，重新启用或绑定不会使它复活。这不取消已通过鉴权的在途请求，也不追回已返回的数据。本地文件柜不删除；离线应用已有的本地状态不由服务端请求鉴权追回。旧独立同步/AI 使用码维持原合同，不受产品设备解绑控制；它们不是两版前端正常登录路径。

新建授权的旧 `licenseId` 输入兼容为客户显示名，不能继续指定存储空间。新空间 ID 由服务端完整产品码 SHA-256 散列派生，不由管理员填写；同一产品码对应同一空间，不同产品码不因显示名或清洗碰撞共享空间。既有云空间 ID 保留且不可变，改客户名称仅修改 `displayName`。

原子唯一性由既有 `ACCOUNT_COORDINATOR` 绑定实现：对同一空间使用相同的 `license-identity:<id>` 对象，其串行队列在一次认领中读取持久 owner、检查历史冲突、再写入唯一 licenseKey。相同 key 可重试，不同 key 被拒绝。owner 在删除授权后不释放；授权自身对象也保留原空间 ID，管理员重建只能回到同一空间。空间认领与授权更新跨两个对象，不是一个全局事务；认领后更新失败最多留下同一产品码的保留空间，重试可继续，不会转让给其他 key。没有新增公共接口、绑定、migration 或 secret。

历史冲突检查读取旧 KV 全部分页并按既有 ID 清洗规则比较；首次认领发现冲突即拒绝，登录/管理保存返回 409，产品同步/AI 不授权。它不是自动修复或备份迁移。未检查线上是否已有冲突；发布前需另行授权，只读核查并备份，停止旧写入并留足 KV 传播时间，再决定空间归属、数据迁移和会话处理。随后只能经管理员接口改授权，直接改 KV 不会覆盖 DO 权威记录。旧无协调器部署的回退路径仍受 KV 传播/并发限制，不能宣称具有同等原子保证；正式强一致闭环依赖仓库既有协调器。没有持久 KV 的环境产品码登录返回 503。

备份恢复（包括旧单班包装）具有明确的全柜覆盖语义，未套用单班导入取消规则。AI 仍只准备建议，教师确认后才写入。配额计数的缺失值仍按 0 初始化，这属于计数器语义；题目 rate 是必需值校验且原值传递，不属于把未知值强转为 0 的可空上下文路径。

这些修复不会追回已经丢失的数据、已导出的旧备份或曾截断的缓存。修复发布后，重新上传/重新生成才会产生符合新规则的备份或 AI 内容。发布顺序与准备事项已记录在 ARCHITECTURE.md、OPERATIONS.md；本次没有执行发布。Space 页面由父任务更新。
