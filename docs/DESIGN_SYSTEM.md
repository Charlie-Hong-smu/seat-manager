本文是 Zhang edition 与 Commercial edition 共用的视觉、组件和交互规范。任何页面重构或新增功能在写 JSX 前先读本文。产品文案和登录方式可以因 edition 不同，视觉语言与交互规则不得分叉。

## 手机工作区（2026-09-22）

窄于 768px 的窗口，以及高度不超过 500px 的横屏触控设备使用手机布局；桌面继续保留已有框架与连续动效。手机主导航按需打开共享 `ModalShell`，正文使用整屏可用宽度；顶栏保留班级、搜索、AI 和账户，云同步收在账户菜单中，保存失败仍显示可重试提示。使用动态视口高度和安全区留白，允许浏览器缩放，输入正文不小于 16px。

评语与宿舍通过共享 `MobilePaneTabs` 展示一个完整操作面：切换只隐藏其他业务面，保留草稿、当前学生、选择和异步任务。评语选人后进入正文，批量选择继续停留名单；横屏正文可滚动到保存区。成绩分析优先占满宽度，考试/导入按需切换；映射弹窗改为纵向内容滚动，确认按钮保持可达。手机上的 pane 入场使用 260ms 短位移，减少动态效果时取消，桌面既有学生交接、图表插值与座位编辑动效不变。

座位保持教室空间关系与可读姓名，允许画布内部横向滚动，工具栏独立横滑。触控以「点选调座」明确进入移动模式，先选学生再选目标，锁定检查与撤销沿用既有逻辑，触屏滑动画布不启动拖动。鼠标保留拖放；等待区保持点选后安排入座。共用按钮/图标操作的手机触控区至少 44px，密集座位的锁定角标和布局行列操作保留较小尺寸，不强行扩大到遮住相邻格。复杂网格与宽表格仍允许内部滚动。

验收须覆盖 320px、390px、手机横屏与较矮视口；比较实际可视位置、触摸操作、保存/取消/撤销和减少动态效果，不能只判断元素存在。测试环境与真机验证须分别说明。本轮验证范围见 `MOBILE_USABILITY.md`。

## 1. 产品气质

这是老师高频使用的桌面工作台，不是营销站，也不是通用后台模板。

- **清晰、克制、可靠**：信息密度可以高，但层级必须一眼可扫；装饰不能抢过学生、成绩和操作结果。
- **浅色中性底 + 白色工作面**：页面背景使用 `--app-bg`，卡片与面板使用 `--app-surface`，边界优先使用细边框和轻阴影。
- **蓝色表示主要操作与当前状态**；AI 能力仅以鸢尾紫小标记和主动生成按钮标识，表面保持中性；红色只表示危险、失败或需要立即关注。
- **圆角统一但不过度胶囊化**：输入和按钮使用 `--app-radius-sm`，卡片和下拉使用 `--app-radius-md`，主面板与大弹窗使用 `--app-radius-lg`。
- **动效解释状态变化**：滑块说明选中项，飞行动画说明对象移动，下拉与抽屉说明层级展开。不要为静态装饰添加持续动画。

## 2. 唯一实现入口

| 需求 | 首选实现 | 禁止的平行实现 |
| --- | --- | --- |
| 主/次/危险/轻按钮 | `Button` | 在页面内重新拼一套相同按钮颜色、圆角和 focus 样式 |
| 纯图标操作 | `IconButton` | 无 `aria-label` 的裸图标按钮 |
| 标准内容卡片 | `Card` | 每页定义不同的边框、阴影和标题间距 |
| 互斥切换 | `SegmentedControl` | 独立按钮组模拟 tab，或没有滑块的同类切换 |
| 普通选项下拉 | `SelectMenu` | 浏览器原生 `select` 或页面内自制选项菜单 |
| 日期选择 | `DatePicker` | 浏览器原生 `input[type=date]` 或各页面自行格式化日期按钮 |
| 标准模态面板 | `ModalShell` | 仅靠透明度隐藏、缺少焦点圈定或关闭后不恢复焦点的局部遮罩 |
| 自定义浮层 | `AnimatedPopover` | 条件渲染导致只有展开动画、没有收起动画 |
| 页签切换 | `UnderlineTabs` + `MotionSwitch` 连续交接 | 静态下划线、内容瞬切或每页独立实现 tab |
| 右侧工具面板 | `ToolDrawer` | 新建结构相同但焦点、Esc、遮罩行为不同的抽屉 |
| 全局 AI 对话 | `AiAssistantLauncher` + `AiAssistantCompanion` | 把完整 AI 页面缩进小框、复制第二套会话状态，或使用阻断当前页面的抽屉遮罩 |
| 文件导入 | `FileDropZone` | 页面内重写拖拽高亮和文件 input |
| 学生搜索选择 | `StudentPicker` 或业务已有选择器 | 每个模块各写一套搜索列表 |
| 姓名跨区域移动 | `animateSelectionTransfer` | 只做淡入、没有目标位置与列表让位的假飞入 |
| 业务确认、提示与破坏性操作 | `ConfirmDialog` / `useAppDialog` | `window.confirm`、`window.alert`、浏览器原生弹窗或页面内临时拼接的确认条 |
| 保存、创建、状态更新的短时反馈 | `ActionToast` / `useActionToast` | 操作成功后完全静默，或各页面复制不同的底部提示条 |
| 页面内持续反馈 | `InlineStatus` | 成功、失败和处理中状态使用同一种颜色或缺少 `role` / `aria-live` |
| AI 生成中状态 | `AiGenerationPanel` | 只放几条模糊横线、无阶段说明，或各业务重新发明一套 loading |
| AI 评语参数与素材操作 | `commentEditor.ts` 共享规则 | 快捷抽屉和评语工作台分别计算字数、选择素材或拼装请求 |
| 跟进任务创建/编辑 | `FollowupTaskForm` | 全局抽屉与任务工作区分别维护字段、来源文案或日期控件 |
| 业务来源与关联状态 | `SourceLink` / `LinkedTaskBadge` / `ResolutionEditor` | 各页面拼接“跟进”“来源”文本或不可点击假链接 |
| 学生当前关注摘要 | `StudentAttentionSummary` | 在学生档案重复复制出勤、作业、任务和成绩判断 |

共享基础组件位于 `frontend-react/src/app/components/ui.tsx`。业务专用但可复用的组件位于同一 `components/` 目录，例如 `StudentPicker.tsx`。共享动效与令牌位于 `frontend-react/src/styles/theme.css`。

判断规则：

1. 已有组件能表达需求时直接复用，通过 props 扩展语义，不复制样式。
2. 同一种结构第二次出现时评估抽取；第三次出现前必须抽取或在代码中说明为何不能共用。
3. 基础组件只负责视觉与通用交互，不读取业务状态、不写 localStorage、不调用 API。
4. 页面组件可以组合基础组件，但不能覆盖它们的核心颜色、圆角、焦点和禁用语义来创造另一套皮肤。

学生搜索统一调用 `state/studentSearch.ts`，姓名与别名使用同一归一化规则；页面不得继续复制大小写、空格和别名匹配逻辑。

## 3. 设计令牌

令牌定义在 `theme.css` 的 `:root`，组件优先引用令牌而不是新增任意值。

### 颜色

- `--app-bg`：应用与工作区底色。
- `--app-surface` / `--app-surface-muted`：主表面与弱表面。
- `--app-border`：默认分隔线与卡片边界。
- `--app-text` / `--app-text-muted`：主文字与辅助文字。
- `--app-primary` / `--app-primary-hover`：主操作、选中和键盘焦点。
- `--app-ai`：AI 入口、生成状态、智能建议。
- `--app-danger`：删除、破坏性确认和错误。

Tailwind 的 `gray`、`blue`、`violet`、`red` 可以用于同色阶状态，但不要在 TSX 中写十六进制颜色，也不要为单页引入新的品牌主色。

### 尺寸与层级

- 顶栏和侧栏标题区基准高度：`h-14`。
- 标准控件高度：小 `h-8`，常规 `h-10`，强调 `h-11`。
- 常规页面间距以 4px 网格组合：8 / 12 / 16 / 20 / 24。
- 卡片阴影使用 `--app-shadow-card`；下拉和抽屉使用 `--app-shadow-float`，弹窗使用 `--app-shadow-modal`。
- 浮层必须有明确层级、视口边界处理和关闭方式，不通过不断增加局部 `z-index` 解决遮挡。
- 从弹窗、抽屉或全屏工作台继续打开另一浮层时，必须先明确层级关系：进入独立详情或编辑流程时关闭来源浮层；必须保留来源上下文时，目标浮层及其遮罩、确认框和下拉须完整位于来源浮层之上。不得出现目标已挂载、可被无障碍树找到，却被来源浮层遮挡的状态。

### 字体层级

- 页面/弹窗标题：`text-base` 或 `text-lg`，`font-bold`。
- 卡片标题：`text-sm` 至 `text-base`，`font-bold`。
- 正文与表格：`text-sm`。
- 标签和必要元数据：`text-xs`，使用弱文字色。辅助说明不得因为字号小、颜色浅就默认常驻；小字仍必须承担明确任务。
- 只有错误、风险、不可逆后果、数据写入边界，或用户无法从当前控件与可见状态判断的关键信息，才使用常驻小字提醒。不得用灰色小字重复标题、按钮含义、占位文字、已可见结果或常识性操作说明；可从布局和状态直接理解的信息应删除，不得以“帮助理解”为由堆叠说明。
- 数值可加粗，但不要同时放大、着色、加阴影造成多重强调。

## 4. 页面与组件规则

### 工作区

- 延续 `AppShell -> TopHeader + Sidebar + workspace` 的稳定骨架。
- 页面首屏先展示老师最需要判断的信息，再展示 AI 建议和次级管理工具。
- “今日”使用三层渐进披露：日期/课表带、最多八项需要处理、四个快捷处理入口；来源详情进入原工作区，不在首页复制完整表格。
- 座位、今日、任务与作业之间通过来源标签和明确跳转互相指向，不在侧栏为课表、作业、周报或题目分析继续增加一级入口。
- 作业登记对 40–60 人班级采用“批量为主、异常为辅”：新作业默认待登记，快速视图先选择目标状态再连续点击学生卡片，提供全部已交、状态计数筛选与单步撤销；点击后原位置卡片短暂高亮、以 `aria-live` 报告结果，并通过六秒 `ActionToast` 提供撤销。默认列表始终保持班级名单顺序，状态变化不得触发重排；只有老师主动使用状态筛选时才缩小列表。逐人下拉和备注只在详细视图出现。旧作业的未交状态不得因界面升级自动改写。
- 出勤登记与作业登记复用“快速 + 详细”的双视图语言：快速视图先选择请假、缺勤、迟到、早退或正常，再连续点击固定顺序的学生卡片；点击后必须原位反馈且不得自动重排。快速登记标题位于整组控件上方，下一行的日期、状态选择和操作按钮同轴排列，不在工具栏之间重复常驻说明。详细视图保留复选批量、组合状态、备注、请假时间和跟进任务。正常状态仍不写记录，旧出勤数据不得因界面升级自动迁移。
- 宿舍周期设置只在“自定义周期”选中时提供，入口出现与消失使用不挤动相邻日期控件的短距离淡入淡出；离开自定义周期时收起尚未保存的设置面板。
- 学科选择统一使用可搜索 `SelectMenu`；默认九科和班级自定义学科来自同一目录，目录编辑进入 `ToolDrawer`，不得在作业表单重新退化为自由文本输入。
- 工具栏优先单行稳定布局；宽度不足时按功能组换行，不让主要按钮随机跳位。
- 来源跳转后的目标使用 `entity-focus-highlight` 短暂高亮并滚动到视口中央；高亮只解释定位，不改变排序。来源已删除时使用灰色不可点击标签并说明原因。
- 条件筛选、清除按钮和关联徽标出现/消失时必须由固定标题栏、稳定网格列或预留操作位吸收，不得推动下面的列表或卡片整体跳动。
- 空状态必须说明下一步；加载和错误状态留在当前工作面内，不整页跳转。

### 卡片与表格

- 同一页面的同级卡片保持一致圆角、边框、标题间距和阴影。
- 带条件操作的卡片标题栏必须预留统一高度；按钮出现或消失不得改变标题栏高度、推动下方内容。标准标题栏由共享 `Card` 组件保证，页面不得另写补丁高度。
- 表格用于精确比较；卡片用于摘要和操作。不要把大量同构数据全部做成装饰卡片。
- 危险操作不能和主要操作使用相同权重；删除需要独立确认或明确的编辑入口。
- 学生联系方式、住址等低频敏感档案默认使用查看模式；必须通过明确的“编辑资料”进入可编辑状态，并提供保存与取消，不能让输入框长期处于可直接修改状态。

### 座位布局编辑器

- 主座位与布局编辑切换复用固定外框和同高工具栏轨道，使用稳定座位 ID 测量起止矩形，以 440ms 单调缓动连续移动与缩放；顶部工具栏同步上下滚动。禁止面板按压回弹、独立网格错位叠显与切换结束后二次入场。目标卡片保持实显，旧卡片沿同一路径退去；切换覆盖的首次槽位启用/卡片入场动画持续禁用，避免收尾闪烁。过渡期间隐藏层和快照均不可交互，结束清理快照并恢复焦点；减少动态效果时直接切换。草稿和应用边界保持不变。

- 默认入口必须直接保留既有八列、相邻两列一组的布局，不要求老师先配置。
- 高级布局在座位主界面进入槽位编辑模式，采用“批量框选 + 单格增删 + 框选成组 + 显式应用”的单一流程；排座弹窗只保留规则。
- 槽位矩阵默认八列居中，列距一致，分组不得插入空走道列；需要更多空间时使用行列边缘加号，单独补充的格子保持未分组。批量框选从左上角连续预览行列范围，确认后以蓝色启用并默认每两列成组。框选成组吸收范围内全部已启用座位，以清晰的琥珀色实线显示拖选范围；已有组框在拖选过程中持续显示，相交组变为红色实线。松手后通过统一确认弹窗，确认才转移相交座位，取消恢复原范围。旧组保留范围外座位；剩余座位被切成多块时按上下左右连通性自动拆组，左上块沿用原名称和 ID，其余块使用不重复的新组号。连通的 L 形或带孔区域沿实际成员绘制，不用外接矩形圈住其他组，轮廓之间保持空隙；空组才移除。讲台始终不属于小组，组框与拖选预览都须为讲台留出缺口或孔洞。
- 框选成组模式支持拖动原组框四边调整范围，方向键可微调，组名与 ID 保留。扩展允许进入相邻组，沿用新增框选的红色碰撞提示、松手确认和旧组收缩拆分逻辑；草稿仅在确认后改变，拖动取消及失焦恢复原范围。悬停整组时边界和成员同步高亮，在左上角显示“编辑”和“解除小组”，键盘聚焦也能访问；普通、批量框选、框选成组模式均可操作，点击组操作不得触发槽位选择。实际拖选期间暂隐组操作，保留组框，松手后恢复。编辑复用统一输入弹窗，可填写组号或组名，空名、重名与超过 24 字的名称阻止确认；手动名称不随自动编号改变。编辑及解除只改分组，不关闭座位，仍需“应用布局”保存，取消布局编辑会丢弃该草稿。
- 行列增删统一使用边缘小图标：上方列间、左侧行间的淡绿色加号插入空列/行；与现有行列中心对齐的淡红色减号删除该行/列，替代底部“加一列 / 加一行”按钮。默认视觉为 11px、18% 不透明度，保留 20px 感应范围；仅单个悬停或键盘聚焦的按钮以 180ms 过渡至 20px、完全可见，禁止整条操作栏共同高亮，鼠标点击后移开也须恢复。删除包含已启用座位或讲台的行列需统一确认弹窗，取消不得改变草稿及当前框选模式。行列范围为 1–25 行、1–20 列，边界处禁用对应操作；插入删除时存活座位复用稳定节点并轻量平移，不重新播放蓝格启用动画、不闪烁；减少动态效果设置下不播放位移动画。
- 编辑、主页面、排座预览和历史座位复用同一响应式槽位几何；常用桌面窗口（1310×690 内容区域）的 8×8 及 66 座布局必须完整显示，不以放大固定比例画布解决重叠。大规模布局和详细卡片允许滚动。旧围桌与手动自由坐标在显式编辑前保留原几何。讲台通过方格悬停动作设置。启用、关闭与框选预览使用 150–360ms 的颜色和轻量缩放动画，同时支持 `prefers-reduced-motion`。
- 正常座位模式的拖动使用独立浮层连续跟手，真实座次只在松手后更新；移入空座时空格和周围座位保持原位，只高亮目标并正常吸附，空格也不参与其他交换的邻座排开。目标有学生时保留交换动画，候选位置与最终吸附必须清楚；主页面与排座预览保持一致。禁止逐小格写回坐标或因碰撞静默停住。
- 空座吸附完成后不再追加淡入；新空座立即稳定显示，不继承拖拽时的透明度过渡。入场动画绑定稳定的槽位容器，学生与空座互换不重复播放。
- 删除或减少座位后，应用前显示座位总数；应用后无法容纳的学生进入持续可见的候补区。候补区保留当前队列顺序，新进入者只追加到末尾，不按名单、姓名或拼音重新排序；候补学生可拖入或先选中再点击空座，不能丢失学生数据。拖入候补区或空座时，真实卡片由拖拽浮层遮住直至吸附结束，不播放透明度恢复造成的落地闪烁。
- 布局编辑中的移动、分组和连线只修改草稿；只有“应用布局”写入当前学期。AI 或自动排座仍须遵守教师确认边界。

### 弹窗、抽屉与下拉

- 弹窗用于需要集中确认的任务；抽屉用于不离开当前上下文的辅助编辑；下拉用于短选择。
- 上下文连续性按以下顺序决策：
  1. 在浮层或全屏工作台内查看关联信息，默认在当前表面内使用只读展开；摘要卡片只负责展开和收起，不得直接跳转工作区。
  2. 只有短辅助编辑才使用位于来源表面之上的抽屉，并通过真实可见性、命中测试与键盘操作验证完整层级，不能只检查 DOM 已挂载。
  3. 完整工作区导航只能由明确的次级按钮触发，按钮必须说明会离开当前流程；触发后再按业务语义关闭来源表面并定位目标。
  4. 确认、危险操作和教师写入确认继续使用共享确认弹窗，不得以只读展开替代必要确认。
- 上下文内事项速览使用普通 `section`、`aria-expanded`、`aria-controls` 与可见焦点，不使用 portal、遮罩或新的 `role="dialog"`。同一上下文一次最多展开一项；切换对象、页签或关闭详情时清除展开状态，但不得清除来源页面的草稿、筛选、选区或滚动位置。已删除或不支持的来源只展示现有历史摘要，不伪造可用入口。
- 全局 AI 对话采用非模态 Companion：关闭时只保留右下角中性悬浮入口（小号鸢尾紫图标标记，忙时以角标小点表示），打开后浮在当前工作区上方但不增加遮罩，老师仍可查看当前页面。桌面端保持约 420px 宽并避开顶栏；小于 640px 时占据顶栏下方的可用宽度。打开后聚焦输入框，Esc 关闭并把焦点返回入口。
- Companion 在同一工作区内只维护一份消息、草稿、生成状态和确认动作；关闭或切换业务页不得重建会话。切换班级/学期时切换到对应工作区缓存，不能把上一工作区对话继续显示为当前事实。
- Companion 打开时不得自动调用 AI。上下文区必须明确显示当前班级、学期、业务页面及实际会附带的摘要；没有附带的数据不得通过文案暗示 AI 已经读取。普通抽屉和未保存表单可被 Companion 暂时覆盖但不得被清空，应用级确认弹窗与 ActionToast 始终位于 Companion 之上。
- 弹窗必须优先使用 `ModalShell`，并具备标题、关闭按钮、Esc 行为、焦点圈定与恢复、可滚动内容区和稳定底部操作区。
- 导入后需要老师决定的数据处理策略使用共享确认弹窗；关闭只代表暂不决定，来源面板必须保留可识别的设置入口和当前选择状态，保存前仍未决定时再次提示，不能把关闭等同于永久拒绝。
- 详情弹窗由实际内容决定高度并设置视口上限；学生详情保留同一外壳及滚动容器，内容多时平滑变高、内容少时平滑缩短（视口减 32px，上限 48rem）。正文可见区域统一承担约 320ms 的高度过渡，达到上限后内部滚动；切换内容从顶部展示，旧滚动位置仅保留在退出画面中，快速切换接续当前高度。
- 下拉统一使用展开与收起动画；靠近视口边缘时应自动换向或使用 portal，避免被父级裁切。
- 业务界面不得新增浏览器原生 `select`。普通枚举选择统一使用 `SelectMenu`；学生选择继续使用 `StudentPicker` / `StudentMultiPicker`，不要用普通下拉替代搜索和选择转移动画。
- 日期选择统一使用中文 `DatePicker`，通过 portal 自动避让视口并提供上月、下月、今天和清除操作；日期与时间组合场景可保留独立时间输入，但不得重新暴露浏览器原生日期面板。
- 关闭后焦点返回触发器；图标按钮必须有可访问名称。
- 删除、清空全部、删除学期等不可撤销操作必须使用共享 `ConfirmDialog`，写清对象、影响范围和不可恢复性；禁止使用 `window.confirm` 或无确认直接执行。
- 普通单项删除使用“取消 / 确认删除”；存在两种安全处理策略时，可增加一个中性备选动作，但红色按钮只能表示破坏性更强的最终动作。
- AI 写入、批量修改、结算、恢复覆盖、设备解绑等业务确认统一通过 `useAppDialog` 调用；普通确认使用蓝色，覆盖、解绑和不可撤销操作使用红色。
- 纯提示与错误信息使用 `useAppDialog().notice`，文本输入使用 `useAppDialog().prompt`，不使用 `window.alert` 或 `window.prompt`。提示弹窗只保留一个清晰的确认按钮。
- 通过折叠动画隐藏但仍留在 DOM 的交互内容必须同时设置 `aria-hidden` 和条件 `inert`；隐藏时传 `true`，显示时传 `undefined`，禁止把 `false` 传给 `inert`。
- 所有显式“创建 / 保存 / 状态更新”操作统一通过 `useActionToast` 给出结果反馈，不得在提交后完全静默。文案直接说明对象和结果，例如“宿舍事件已保存”，不得只写“成功”。
- 新建数据默认在 `ActionToast` 中提供 6 秒“撤销”；撤销必须完整回滚本次创建及其同步产生的关联数据，不能只移除当前列表项。编辑保存或状态更新在能够可靠恢复旧值时也提供撤销；无法安全回滚时不得放置无效的撤销按钮。
- 跨领域撤销同时恢复任务、来源状态和本次 `activityEvents`；只恢复页面外观但保留历史动作视为无效撤销。
- 跟进完成默认单击立即生效，处理结果为可选的第二步；来源可同步时使用应用内确认弹窗询问，不能把来源状态静默覆盖。
- 多人共同事项的表单始终显示“创建任务”，列表一张卡片展示所有参与者，编辑与继续跟进保留完整名单；一般逐人业务批量创建显示“分别创建 N 项”。同一作业的逐人补交任务在列表合成一张事项卡，卡内逐人操作并展示各自状态，创建入口显示人数；其他逐人业务仍分别列出。已有逐人任务的学生与个人来源固定，不能通过编辑把另一个学生的结果混入。任务数按可见事项计，学生详情对每位参与者可见；旧任务不得仅凭同名标题自动合并。
- 如果当前工作面已有紧邻操作对象、持续可见的成功/失败状态，可保留内联反馈；全局自动保存继续使用顶栏持久状态，不触发 Toast，避免保存草稿或输入变化时反复打扰。
- 除密码、授权码和一次性敏感字段外，业务文本框的用户输入必须按工作区与业务对象自动缓存；关闭弹窗、退出工作台、切换页面或组件卸载后重新进入，必须恢复尚未正式提交的内容。缓存只保障草稿可恢复，不得冒充正式保存、绕过确认或触发外部写入；正式保存成功后再按业务规则合并或清理缓存。不得让用户因为退出再进入而丢失已经输入或已确认应用的文字。

## 5. 动效规范

统一缓动优先使用 `cubic-bezier(0.22, 1, 0.36, 1)`。

- 微交互/颜色：150–220ms。
- 下拉与内容切换：180–300ms。
- 同一弹窗或详情页的相邻页签使用 `UnderlineTabs` 的滑动指示条；正文原位交接，明确的上一位/下一位姓名导航保留短方向位移。弹窗随内容高度连续居中，标题栏和页签不得硬跳或额外横移。
- 弹窗进入 320ms、退出 240ms；背景与面板独立过渡，使用统一单调缓动。
- 抽屉与布局重排：300–440ms。
- 对象飞入、交换、吸附：520–760ms，可带轻微回弹但不能模糊最终位置。
- 所有新增动效必须支持 `prefers-reduced-motion`，且不能阻塞点击后的数据提交。
- 列表新增/删除使用 FLIP 或 `animateSelectionTransfer` 让其他项自然让位、合拢；不要瞬移后再播放无关淡入。
- 整版 FLIP（如座位简洁/详细切换）只允许动画 `transform`；`height`、`clip-path` 等属性在多元素上会退回主线程逐帧排布/光栅化导致掉帧。位移窗口内给容器打 `[data-seat-settling]` 静音子孙的 CSS 过渡，让卡片内部排布直接落位。

### AI 生成动效

- 预计会让教师等待的 AI 生成统一使用 `AiGenerationPanel`；空间受限时可使用其紧凑模式，不得退化成只有几条模糊横线闪烁的占位符。
- 生成状态的入口与操作使用鸢尾紫 AI 语义、加载动画保持单色点阵，展示明确标题和 2–4 个与当前任务对应的处理阶段；阶段只解释正在做什么，不伪造百分比或完成时间。
- 重新生成时先收起旧结果，生成完成后使用 `ai-followup-result-enter` 和容器展开动效呈现新结果，避免内容瞬间替换。
- `prefers-reduced-motion` 下停止扫描、旋转和脉冲等循环动画，但保留当前阶段文字、结果状态和所有操作能力。
- 今日列表完成后只做 150–220ms 收起与补位，随后使用六秒可撤销 `ActionToast`；课表、周报、快捷记录和作业编辑统一进入现有抽屉或页签，不使用新的全屏过场。
- AI 输出必须是教师可直接阅读的自然中文。内部 JSON 字段名、英文指标名和模型调试信息不得进入结果卡片；生成端约束与展示端规范化必须同时防护旧缓存和异常响应。
- AI 请求若使用“学生A”等脱敏占位身份，展示层必须根据本地稳定关联（优先学生 ID）还原为当前真实姓名，旧缓存读取也必须经过同一还原；不得把占位身份直接显示给教师。还原只发生在本地展示层，不以改善文案为由把真实姓名重新加入原本已脱敏的请求。
- 同一 AI 能力存在快捷入口和完整工作台时，可以采用不同信息密度，但必须共享参数规则、素材操作、缓存、生成状态机和结果保存逻辑；不得只追求视觉相似而保留两套业务实现。
- 评语正文的局部 AI 编辑只在存在非空文字选区时显示紧邻选区的操作条；按钮仅在鼠标悬停或执行当前动作时加深中性色。点击动作后必须在正文自身的文字流中用浅灰底线标示正在优化的选中文字并保留可读内容，不测量选区坐标、不叠加扫描浮层，标记与正文一起自然滚动。返回后在同一文字流中用稳定的蓝色删除线标记原句，并让建议紧随其后、带动后文自然重排；不得用白底、边框、阴影或独立浮层伪装成正文。正文已经同时呈现原句和建议时，不再重复显示原文/建议卡或解释性小字，只保留一个“应用 AI 修改”动作；老师点击后才修改当前草稿，最终持久化仍使用页面既有保存动作。Esc 先放弃当前建议，不直接退出工作台。

## 6. UI 开发流程

每次新增或修改界面按以下顺序：

1. 找到同类已完成页面和现有基础组件。
2. 判断问题是否来自共享样式、基础组件、缓存策略或重复交互；若可能是共性问题，搜索全部同类调用点，按业务语义分类，并在当前改动中一并修复同根缺陷。取消即放弃、敏感字段等刻意例外必须在交接中说明，不能只修截图中的单一页面。
3. 写清楚信息优先级、主要动作、危险动作、空/加载/错误状态。
4. 先用现有令牌与组件组合；只有缺少通用能力时才扩展基础组件。
5. 同时检查默认版和商用版，不根据某一个浏览器快照硬编码产品数据。
6. 运行 `pnpm check:design`、lint、strict typecheck、覆盖率和双 edition build。
7. 用浏览器在常用桌面宽度检查视觉，并至少验证键盘 focus、Esc、浮层边界、嵌套浮层实际层级和 reduced motion。凡从一个浮层触发另一个浮层，回归测试必须同时断言来源已关闭，或通过可见性与命中测试确认目标处于最上层；只断言目标 DOM 已存在不算通过。

## 7. 验收清单

- [ ] 第一眼能分辨页面标题、当前状态和唯一主要动作。
- [ ] 蓝色操作 / 鸢尾紫 AI / 红色危险的语义没有混用。
- [ ] 同级控件高度、圆角、间距一致。
- [ ] 没有新增与 `ui.tsx` 等价的局部组件或复制样式。
- [ ] 下拉、弹窗、抽屉不会被裁切，展开和收起都有动画。
- [ ] 从弹窗、抽屉或全屏工作台打开下一层界面时，来源已按业务语义关闭，或目标浮层、遮罩及其子浮层实际位于来源之上；浏览器测试未仅以 DOM 存在作为层级通过条件。
- [ ] 浮层内的关联摘要默认原位只读展开，一次最多一项，没有新增遮罩或弹窗；摘要卡片不直接跳转，只有明确的完整页面入口才会离开当前流程。
- [ ] 收起关联摘要或关闭子详情后，来源工作台的学生、草稿、选区、筛选和滚动位置保持不变。
- [ ] 业务界面没有浏览器原生 `select`，普通选项使用 `SelectMenu`，学生选择使用共享学生选择器。
- [ ] 业务界面没有浏览器原生 `input[type=date]` 或 `input[type=datetime-local]`，日期选择统一使用 `DatePicker`，时间按需使用独立 `input[type=time]`。
- [ ] 新增/删除对象时，来源、目标和最终位置清楚。
- [ ] hover、focus-visible、disabled、loading、empty、error 状态完整。
- [ ] 所有持久数据删除与清空均使用 `ConfirmDialog`，不存在浏览器原生删除确认框。
- [ ] 页面中不存在 `window.confirm`、`window.alert` 或 `window.prompt`；业务确认、错误、提示和文本输入均使用共享应用内弹窗。
- [ ] 模态面板使用 `ModalShell` 或同等共享入口，关闭后恢复焦点，Tab 不会逃出当前弹窗。
- [ ] TSX 中不存在十六进制颜色；图表和装饰色也从 `theme.css` 令牌读取。
- [ ] 显式创建/保存/状态更新使用共享 `ActionToast`；新建数据默认可撤销且关联数据一并回滚，自动保存不会反复弹出。
- [ ] `prefers-reduced-motion` 下功能仍可用。
- [ ] AI 生成使用共享阶段动效，结果为自然中文且不泄露内部英文字段名。
- [ ] 使用脱敏身份的 AI 结果已在本地按稳定关联还原真实姓名，旧缓存与新响应表现一致。
- [ ] 已扫描共享模式和同类调用点；同根缺陷已一并修复，刻意保留的业务例外已记录。
- [ ] Zhang 与 Commercial edition 的页面结构和视觉语言一致。
- [ ] 没有改变登录、持久数据、备份、同步或 AI 确认边界。

## 8. Codex 交接格式

完成 UI 工作时，交接应说明：

- 复用了哪些基础组件或令牌；
- 新增了什么通用模式，以及为什么需要；
- 在哪些页面、edition 和状态下做了视觉验证；
- 是否存在刻意保留的例外。

不要只说“UI 已优化”。这能让下一个对话知道设计决策，而不必从截图重新猜测。
