# 产品设计系统

本文是 Zhang edition 与 Commercial edition 共用的视觉、组件和交互规范。任何页面重构或新增功能在写 JSX 前先读本文。产品文案和登录方式可以因 edition 不同，视觉语言与交互规则不得分叉。

## 1. 产品气质

这是老师高频使用的桌面工作台，不是营销站，也不是通用后台模板。

- **清晰、克制、可靠**：信息密度可以高，但层级必须一眼可扫；装饰不能抢过学生、成绩和操作结果。
- **浅色中性底 + 白色工作面**：页面背景使用 `--app-bg`，卡片与面板使用 `--app-surface`，边界优先使用细边框和轻阴影。
- **蓝色表示主要操作与当前状态**；紫色只表示 AI 或智能辅助；红色只表示危险、失败或需要立即关注。
- **圆角统一但不过度胶囊化**：输入和按钮使用 `--app-radius-sm`，卡片和下拉使用 `--app-radius-md`，主面板与大弹窗使用 `--app-radius-lg`。
- **动效解释状态变化**：滑块说明选中项，飞行动画说明对象移动，下拉与抽屉说明层级展开。不要为静态装饰添加持续动画。

## 2. 唯一实现入口

| 需求 | 首选实现 | 禁止的平行实现 |
| --- | --- | --- |
| 主/次/危险/轻按钮 | `Button` | 在页面内重新拼一套相同按钮颜色、圆角和 focus 样式 |
| 纯图标操作 | `IconButton` | 无 `aria-label` 的裸图标按钮 |
| 标准内容卡片 | `Card` | 每页定义不同的边框、阴影和标题间距 |
| 互斥切换 | `SegmentedControl` | 独立按钮组模拟 tab，或没有滑块的同类切换 |
| 普通选项下拉 | `SelectMenu` | 浏览器原生 `select` 或页面内自制选项菜单 |
| 日期选择 | `DatePicker` | 浏览器原生 `input[type=date]` 或各页面自行格式化日期按钮 |
| 自定义浮层 | `AnimatedPopover` | 条件渲染导致只有展开动画、没有收起动画 |
| 页签切换 | `UnderlineTabs` + 方向性内容进入动效 | 静态下划线、内容瞬切或每页独立实现 tab |
| 右侧工具面板 | `ToolDrawer` | 新建结构相同但焦点、Esc、遮罩行为不同的抽屉 |
| 文件导入 | `FileDropZone` | 页面内重写拖拽高亮和文件 input |
| 学生搜索选择 | `StudentPicker` 或业务已有选择器 | 每个模块各写一套搜索列表 |
| 姓名跨区域移动 | `animateSelectionTransfer` | 只做淡入、没有目标位置与列表让位的假飞入 |
| 业务确认、提示与破坏性操作 | `ConfirmDialog` / `useAppDialog` | `window.confirm`、`window.alert`、浏览器原生弹窗或页面内临时拼接的确认条 |
| AI 生成中状态 | `AiGenerationPanel` | 只放几条模糊横线、无阶段说明，或各业务重新发明一套 loading |
| AI 评语参数与素材操作 | `commentEditor.ts` 共享规则 | 快捷抽屉和评语工作台分别计算字数、选择素材或拼装请求 |

共享基础组件位于 `frontend-react/src/app/components/ui.tsx`。业务专用但可复用的组件位于同一 `components/` 目录，例如 `StudentPicker.tsx`。共享动效与令牌位于 `frontend-react/src/styles/theme.css`。

判断规则：

1. 已有组件能表达需求时直接复用，通过 props 扩展语义，不复制样式。
2. 同一种结构第二次出现时评估抽取；第三次出现前必须抽取或在代码中说明为何不能共用。
3. 基础组件只负责视觉与通用交互，不读取业务状态、不写 localStorage、不调用 API。
4. 页面组件可以组合基础组件，但不能覆盖它们的核心颜色、圆角、焦点和禁用语义来创造另一套皮肤。

## 3. 设计令牌

令牌定义在 `theme.css` 的 `:root`，组件优先引用令牌而不是新增任意值。

### 颜色

- `--app-bg`：应用与工作区底色。
- `--app-surface` / `--app-surface-muted`：主表面与弱表面。
- `--app-border`：默认分隔线与卡片边界。
- `--app-text` / `--app-text-muted`：主文字与辅助文字。
- `--app-primary` / `--app-primary-hover`：主操作、选中和键盘焦点。
- `--app-ai`：AI 入口、生成状态、智能建议。
- `--app-danger`：删除、破坏性确认和错误。

Tailwind 的 `gray`、`blue`、`violet`、`red` 可以用于同色阶状态，但不要在 TSX 中写十六进制颜色，也不要为单页引入新的品牌主色。

### 尺寸与层级

- 顶栏和侧栏标题区基准高度：`h-14`。
- 标准控件高度：小 `h-8`，常规 `h-10`，强调 `h-11`。
- 常规页面间距以 4px 网格组合：8 / 12 / 16 / 20 / 24。
- 卡片阴影使用 `--app-shadow-card`；下拉、弹窗、抽屉使用 `--app-shadow-float`。
- 浮层必须有明确层级、视口边界处理和关闭方式，不通过不断增加局部 `z-index` 解决遮挡。

### 字体层级

- 页面/弹窗标题：`text-base` 或 `text-lg`，`font-bold`。
- 卡片标题：`text-sm` 至 `text-base`，`font-bold`。
- 正文与表格：`text-sm`。
- 标签、提示、元数据：`text-xs`，使用弱文字色。
- 数值可加粗，但不要同时放大、着色、加阴影造成多重强调。

## 4. 页面与组件规则

### 工作区

- 延续 `AppShell -> TopHeader + Sidebar + workspace` 的稳定骨架。
- 页面首屏先展示老师最需要判断的信息，再展示 AI 建议和次级管理工具。
- 工具栏优先单行稳定布局；宽度不足时按功能组换行，不让主要按钮随机跳位。
- 空状态必须说明下一步；加载和错误状态留在当前工作面内，不整页跳转。

### 卡片与表格

- 同一页面的同级卡片保持一致圆角、边框、标题间距和阴影。
- 表格用于精确比较；卡片用于摘要和操作。不要把大量同构数据全部做成装饰卡片。
- 危险操作不能和主要操作使用相同权重；删除需要独立确认或明确的编辑入口。
- 学生联系方式、住址等低频敏感档案默认使用查看模式；必须通过明确的“编辑资料”进入可编辑状态，并提供保存与取消，不能让输入框长期处于可直接修改状态。

### 弹窗、抽屉与下拉

- 弹窗用于需要集中确认的任务；抽屉用于不离开当前上下文的辅助编辑；下拉用于短选择。
- 弹窗必须有标题、关闭按钮、Esc 行为、可滚动内容区和稳定底部操作区。
- 详情弹窗默认由实际内容决定高度，并设置视口上限；内容较少时不得强行撑满。页签切换或内容增删引起的高度变化使用 300ms 左右的统一缓动，达到上限后才启用内部滚动。
- 下拉统一使用展开与收起动画；靠近视口边缘时应自动换向或使用 portal，避免被父级裁切。
- 业务界面不得新增浏览器原生 `select`。普通枚举选择统一使用 `SelectMenu`；学生选择继续使用 `StudentPicker` / `StudentMultiPicker`，不要用普通下拉替代搜索和选择转移动画。
- 日期选择统一使用中文 `DatePicker`，通过 portal 自动避让视口并提供上月、下月、今天和清除操作；日期与时间组合场景可保留独立时间输入，但不得重新暴露浏览器原生日期面板。
- 关闭后焦点返回触发器；图标按钮必须有可访问名称。
- 删除、清空全部、删除学期等不可撤销操作必须使用共享 `ConfirmDialog`，写清对象、影响范围和不可恢复性；禁止使用 `window.confirm` 或无确认直接执行。
- 普通单项删除使用“取消 / 确认删除”；存在两种安全处理策略时，可增加一个中性备选动作，但红色按钮只能表示破坏性更强的最终动作。
- AI 写入、批量修改、结算、恢复覆盖、设备解绑等业务确认统一通过 `useAppDialog` 调用；普通确认使用蓝色，覆盖、解绑和不可撤销操作使用红色。
- 纯提示与错误信息使用 `useAppDialog().notice`，不使用 `window.alert`。提示弹窗只保留一个清晰的确认按钮。

## 5. 动效规范

统一缓动优先使用 `cubic-bezier(0.22, 1, 0.36, 1)`。

- 微交互/颜色：150–220ms。
- 下拉与内容切换：180–300ms。
- 同一弹窗或详情页的相邻页签使用 `UnderlineTabs` 的滑动指示条；内容按目标页签方向轻量滑入。不得让整个弹窗位移，也不得因不同内容高度导致标题栏和页签跳动。
- 抽屉与布局重排：300–440ms。
- 对象飞入、交换、吸附：520–760ms，可带轻微回弹但不能模糊最终位置。
- 所有新增动效必须支持 `prefers-reduced-motion`，且不能阻塞点击后的数据提交。
- 列表新增/删除使用 FLIP 或 `animateSelectionTransfer` 让其他项自然让位、合拢；不要瞬移后再播放无关淡入。

### AI 生成动效

- 预计会让教师等待的 AI 生成统一使用 `AiGenerationPanel`；空间受限时可使用其紧凑模式，不得退化成只有几条模糊横线闪烁的占位符。
- 生成状态使用紫色 AI 语义，展示明确标题和 2–4 个与当前任务对应的处理阶段；阶段只解释正在做什么，不伪造百分比或完成时间。
- 重新生成时先收起旧结果，生成完成后使用 `ai-followup-result-enter` 和容器展开动效呈现新结果，避免内容瞬间替换。
- `prefers-reduced-motion` 下停止扫描、旋转和脉冲等循环动画，但保留当前阶段文字、结果状态和所有操作能力。
- AI 输出必须是教师可直接阅读的自然中文。内部 JSON 字段名、英文指标名和模型调试信息不得进入结果卡片；生成端约束与展示端规范化必须同时防护旧缓存和异常响应。
- AI 请求若使用“学生A”等脱敏占位身份，展示层必须根据本地稳定关联（优先学生 ID）还原为当前真实姓名，旧缓存读取也必须经过同一还原；不得把占位身份直接显示给教师。还原只发生在本地展示层，不以改善文案为由把真实姓名重新加入原本已脱敏的请求。
- 同一 AI 能力存在快捷入口和完整工作台时，可以采用不同信息密度，但必须共享参数规则、素材操作、缓存、生成状态机和结果保存逻辑；不得只追求视觉相似而保留两套业务实现。

## 6. UI 开发流程

每次新增或修改界面按以下顺序：

1. 找到同类已完成页面和现有基础组件。
2. 写清楚信息优先级、主要动作、危险动作、空/加载/错误状态。
3. 先用现有令牌与组件组合；只有缺少通用能力时才扩展基础组件。
4. 同时检查默认版和商用版，不根据某一个浏览器快照硬编码产品数据。
5. 运行 `pnpm check:design`、lint、strict typecheck、覆盖率和双 edition build。
6. 用浏览器在常用桌面宽度检查视觉，并至少验证键盘 focus、Esc、浮层边界和 reduced motion。

## 7. 验收清单

- [ ] 第一眼能分辨页面标题、当前状态和唯一主要动作。
- [ ] 蓝 / 紫 / 红的语义没有混用。
- [ ] 同级控件高度、圆角、间距一致。
- [ ] 没有新增与 `ui.tsx` 等价的局部组件或复制样式。
- [ ] 下拉、弹窗、抽屉不会被裁切，展开和收起都有动画。
- [ ] 业务界面没有浏览器原生 `select`，普通选项使用 `SelectMenu`，学生选择使用共享学生选择器。
- [ ] 业务界面没有浏览器原生 `input[type=date]`，日期选择统一使用 `DatePicker`。
- [ ] 新增/删除对象时，来源、目标和最终位置清楚。
- [ ] hover、focus-visible、disabled、loading、empty、error 状态完整。
- [ ] 所有持久数据删除与清空均使用 `ConfirmDialog`，不存在浏览器原生删除确认框。
- [ ] 页面中不存在 `window.confirm` 或 `window.alert`；业务确认、错误和提示均使用共享应用内弹窗。
- [ ] `prefers-reduced-motion` 下功能仍可用。
- [ ] AI 生成使用共享阶段动效，结果为自然中文且不泄露内部英文字段名。
- [ ] 使用脱敏身份的 AI 结果已在本地按稳定关联还原真实姓名，旧缓存与新响应表现一致。
- [ ] Zhang 与 Commercial edition 的页面结构和视觉语言一致。
- [ ] 没有改变登录、持久数据、备份、同步或 AI 确认边界。

## 8. Codex 交接格式

完成 UI 工作时，交接应说明：

- 复用了哪些基础组件或令牌；
- 新增了什么通用模式，以及为什么需要；
- 在哪些页面、edition 和状态下做了视觉验证；
- 是否存在刻意保留的例外。

不要只说“UI 已优化”。这能让下一个对话知道设计决策，而不必从截图重新猜测。
