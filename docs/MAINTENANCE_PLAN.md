# 维护优化计划

基于 2026-09-26 对 `1262296` 的审查。目标是减少重复发布检查、为首屏体积留出余量，并逐步降低领域模块的修改成本；保留当前界面、连续动效、数据格式和双版发布方式。

## 基线与判断

应用前端非测试源码约 174 文件、37,360 行，已采用严格 TypeScript、共享 UI、状态控制器、覆盖率门槛和双版本浏览器检查。局部 import/re-export 静态扫描未发现环，不代表排除了运行时耦合。当前值得治理的集中点如下，文件行数仅用于定位，不作为拆分目标。

| 范围 | 审查基线 | 具体影响 |
| --- | --- | --- |
| 首屏入口 | gzip 217.0 KiB / 220 KiB；PWA precache 1.96 MiB / 2.25 MiB | 新增普通功能容易触及入口预算 |
| 发布流程 | Zhang 已验收同一 SHA，Commercial 再跑一遍共享全套检查 | 重复耗时；旧流程未自动核验 Zhang 成功证据 |
| 文档 | 交接日期停在 7 月，仍有预览限定、待晋升及 Worker 已拆分描述 | 新会话容易误判状态或重复治理 |
| Worker | `worker-app.js` 约 1,910 行；`routes/` 多为薄转发层 | 领域行为与装配仍集中，修改影响难隔离 |
| 前端协调 | `App.tsx` 约 1,404 行；评语 1,450、宿舍 1,051、学生弹窗 935 行 | 多个编辑、异步、草稿状态混在同一协调层 |
| 共享样式与组件 | `theme.css` 3,240 行、`ui.tsx` 1,222 行 | 属于统一设计入口；单纯行数大不足以支持拆分 |

## 执行顺序和验收

| 阶段 | 工作 | 验收条件 | 本轮范围 |
| --- | --- | --- | --- |
| 1. 校正文档与发布证据 | 统一当前事实；Commercial 核验同一完整 SHA、同一次运行的必要 job/step 和 Zhang 部署；有新契约证据才复用共享检查 | 错 SHA、缺失/跳过/失败、API 错误均阻止；旧版回滚保留全量验证；Commercial 环境构建和上线检查保留 | 实现并本地验证，实际 CI 行为待后续发布验证 |
| 2. 首屏减负 | 宿舍、班费、历史、名单/备份接入已有 `RetryableLazy`；应用入口直接导入同步页面，避免 barrel 副作用把异步页拉回入口 | 入口 gzip 低于 200 KiB；四个新 chunk 不在初次页面请求；冷加载中切走不抢回页面，热加载离线回访正常；持久数据及既有动画回归通过 | 实现并验证 |
| 3. Worker 领域分离 | 先提取手动同步 handler，再按授权、管理、AI 逐个独立改动；保留当前 handler 签名及路由分发 | 公共路由、状态码、错误/CORS、鉴权和 KV 键保持；同步保留前端已发送的整柜与旧单班字段；Worker 和 Netlify 契约测试通过 | 手动同步已提取并补齐整柜保存；授权、管理、AI 后续各自独立验收 |
| 4. 前端业务协调拆分 | 先宿舍事件编辑草稿，再学生详情编辑会话，最后评语单人编辑与批量生成任务；沿现有 action/selector/storage 边界提取 | 编辑/保存/取消/撤销、刷新、跨学生/跨班级切换、异步过期结果及移动端连续动效均有回归；状态仍只有一个持久来源 | 后续，每个模块独立提交和验收 |

第三阶段先选择相对独立的手动同步，是为了检验领域拆分方式；授权和 AI 额度的并发、兼容风险更高，必须单独审查。第四阶段不按文件行数机械拆分：先写清草稿拥有者、保存边界、取消行为和异步生命周期，再移动代码。`App` 保留导航与跨领域协调，领域事件进入已有专用 action；禁止引入通用万能 hook 或无业务意义的转发组件。

## 本轮测量与交付边界

两版入口 gzip 均为 191.5 KiB，对照优化前的 217.0 KiB 约减少 11.8%，PWA precache 仍为 1.96 MiB。按需加载减少首次执行的入口代码；PWA 后台仍预缓存离线资源，因此不把入口减量表述为总下载量或实际首屏时间的等比例降低。

已用 GitHub 只读 API 验证现有发布 `12622969ddfd9f3f8ef819baf4693201ad1eae9f`：找到 Zhang run `36205514834`、attempt 1，正确识别为旧契约并选择全量检查。新契约的成功/失败路径使用自动测试覆盖；尚未运行修改后的线上 workflow，因此不声明实际发布提速。

本地验证（2026-09-26）：设计检查、lint、严格类型检查通过；前端 62 个测试文件共 293 项通过，核心覆盖率为语句 81.96%、分支 76.31%、函数 81.57%、行 83.7%；Worker 25 项、发布证据门禁 17 项通过。两个版本的生产构建和体积检查、Commercial 生产包检查均通过，两个 workflow 的 YAML 语法检查通过。

浏览器完整回归：Zhang 96/96 通过；Commercial 首轮 67/69 通过，两项失败均为原测试对同步加载的假设。导航计时改为包含模块准备的点击至运动时间；宿舍事件初始化会更换初始 DOM，元素身份探针改为等待真实页面可操作后设置，并为宿舍/班费/历史同类探针排除动画副本。保留几何、透明度、焦点、保存/取消及原位编辑检查，应用动效源码未修改。随后两版各 5 项相关场景定向复测全部通过；未重复运行无关已通过场景。新增按需加载、加载中切走、离线热回访与持久化测试在两版完整回归中通过。截图、首次失败现场保存在本工作区忽略目录 `.local-recovery/maintenance-validation/`，不会提交。

改动保存在 `codex/maintenance-baseline` 独立工作区，main、现有预览、正式浏览器数据和线上版本不随本轮优化自动改变。没有存储迁移或公共路由变更。验收完成后即结束本轮，后续领域拆分按本计划逐项推进，不顺带改写样式系统或增加功能。

## 第二轮：手动同步领域

`worker-app.js` 从 1,910 行减少到1,699 行；`routes/sync-routes.js` 直接拥有同步行为，移除只转发一次的工厂函数。共享请求读取和旧文本转换进入 `worker-input.js`，授权与同步共同使用 `worker-license-keys.js`，12 小时会话常量由 `worker-auth.js` 提供。领域模块不导入应用装配入口，没有新建请求级全局状态。

联查前端、Worker、Netlify 代理和部署路径时发现：前端已发送整柜，但原 Worker 忽略了 `workspaceBook`。新增测试先在旧实现上复现丢失，再修复保存和读取两个方向；保持 `data`、旧 KV 键和已有鉴权行为。完整备份仍受 5 MiB 限制，写入失败不会返回成功。旧云记录缺失的班级不能由此修复自动找回，需要后续部署后从完整本机文件柜重新手动上传。

本轮浏览器回归使用正式前端和实际 Worker 授权/同步 handler，只有网络传输与 KV 为本地测试替身；覆盖两班三学期上传、取消不请求恢复、确认后下载本机安全备份、完整恢复与刷新持久化。Commercial 代理另有完整请求/响应往返测试。线上 KV 和用户浏览器数据不参与测试。

第二轮验证（2026-09-26）：Worker 与代理 34 项测试通过；前端 lint、严格类型检查、62 文件 293 项覆盖率测试通过（覆盖率与第一轮相同）；两版生产构建、体积检查和 Commercial 生产包检查通过；新增整柜浏览器回归两版各 1 项通过；Wrangler dry-run 通过（gzip 19.60 KiB），未部署。首次浏览器测试将确认框写成 dialog，修正为共享组件实际使用的 alertdialog 后通过，产品 UI 未修改。共享请求/文本工具仅搬移原实现，前端产品代码未修改，因此不重复无关全量浏览器回归。
