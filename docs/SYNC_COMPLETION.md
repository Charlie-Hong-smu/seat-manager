## 实施与安全边界

1. 逐空间迁移需要发布门禁和受信部署截断清单；清单指定空间、备份摘要、旧写退役边界。教师请求不能伪造该清单，不能仅依赖客户端版本登记。
2. 迁移请求显式确认全部班级学期，队列内冻结目标空间的新旧 save。已接收的新 Worker 旧协议写保留可恢复来源；没有来源见证时只接受与截断清单固定摘要一致的 KV 候选，陈旧读取不允许提交。
3. 冻结、备份准备、确认提交、取消和完成阶段持久化。512 KiB 分块保存原始备份和完整性摘要；确认后从固定备份事务创建 head，提交不再次读取 KV。重启可继续同一操作；提交重复不增 revision；已创建 head 永不撤回 KV。
4. 提供备份导出/核验及迁移 UI。真实旧 Worker 退役/在途写结束和来源备份证明仍需要运营授权；本轮仅用合成数据测试，不能用假运营清单声称线上已收口。
5. 自动模式提供首次整柜/空间确认、停用、显式恢复、按空间持久偏好。启动只恢复已有有效同空间授权，换账号/epoch/冲突/存储故障暂停；不为既有教师创建同意记录。
6. 单一调度计时器带会话资格检查。冲突立即暂停，所有定时器退出后无后续上传；启用时 checkpoint 失败回滚客户端资格，服务端 strict 保留以阻止旧盲写。
7. 开启路径使用真实公共接口、合成产品授权与 SQLite 验收；专门的临时开启构建不得成为生产 Pages 产物。

## 最终实现审查

- GET 不再根据全局开关隐式导入一次 KV；逐空间迁移须固定备份、阶段持久化及老师确认，失败可以继续同 operationId 或取消。旧 SQLite head 补证不改变 epoch/revision，删除清理备份/历史/回执但保留证明与 tombstone。服务端新能力失败不退回 KV 盲写。
- 启用同时核对老师刚确认的目标空间、有效绑定、同 epoch 和本机/确认基线/权威 hash 一致；旧备份读档补齐默认字段后先一键同步建立新确认基线。服务端 mode 回执和客户端 checkpoint/独立 consent 偏好落盘后才安排自动发送。后续暂停、换账号、epoch、冲突、quota、完全不可访问的本机存储均先撤销内存资格并失效回执；无法持久化暂停时尽力清除偏好。
- 单一计时器避免多个重试或失效会话继续上传；suspend 仅退出当前实例，disable 明确写停用，pause 保留需要明确恢复的原因。手动上传/恢复仍显式选择方向。正式 flush 期间忽略自身写通知；切班同业务 hash 不触发查询/上传循环。丢响应的老回执不会遮蔽已知的更新云端 head。
- 远端替换前保存本机/云端恢复点；checkpoint 写失败尝试恢复本机，回滚也失败时准确显示“确认基线和本机回滚均失败”并暂停，保留可导出的恢复点。草稿、旧 AI 和撤销代际由真实 React + workerd/SQLite 联合用例验证。
- 扫描全部共享草稿 hook 调用点：新任务/作业/班费等表单回到初始值时没有活动草稿；编辑已有正文清空仍是修改；磁盘 clear 失败以内存 tombstone 遮蔽旧草稿。布局与排座预览沿用明确取消丢弃边界。隐藏/inert/aria-hidden 祖先下的日期弹层不算活动编辑面，当前同步弹窗自身也不阻止拉取。
- UI 使用现有 ModalShell、应用确认弹窗、Button 和 theme tokens；迁移阶段使用中文，首次启用明确全部班级学期、目标空间和旧版写入限制。390px 开启路径检查触摸目标与横向溢出；原 320/390px、矮横屏/减少动态效果测试继续保留。没有修改 App.tsx 或手机任务源码。
- Pages v2 必须有两版开启路径成功步骤才能复用验证证据。开启构建独立目录不上传 Pages；旧批准提交的 Commercial 回滚可走原全量验证，不要求不存在的新增脚本。修改工作流不等于触发 Commercial 发布。
